# Codex Agent Operations

실행 환경과 내가 파일을 읽고/수정/검증/버전 관리할 때 쓰는 방법 정리.

- **환경**: Windows cmd 실행기 위에 Codex CLI. 현재 설정은 `danger-full-access`, 네트워크 사용 가능, 승인 정책은 `never`(승인 요청 없이 해결해야 함).
- **주요 도구**: `rg`(ripgrep 15.1.0)으로 검색, `cmd /C dir`로 디렉터리 확인, `cmd /C type <file>`로 파일 보기. `python`은 없음(명령 실패), `node`는 v22.19.0 사용 가능.
- **파일 읽기**:
  - 짧은 파일: `cmd /C "type path\to\file"`.
  - 검색: `rg "pattern" path` 또는 `rg -n "pattern" file`.
  - 특정 구간만 보기(파이썬 없음 → Node 사용):  
    `cmd /C node -e "const fs=require('fs'); const lines=fs.readFileSync('path','utf8').split(/\\r?\\n/); const s=100,e=140; for(let i=s-1;i<e;i++) console.log((i+1)+':'+lines[i]);"`  
    라인 수가 큰 파일은 이렇게 범위 출력.
- **파일 편집**:
  - 기본은 `apply_patch`로 수정/추가. ASCII 유지, 불필요한 주석/노이즈 금지.
  - 단일 파일에 대한 수작업 변경에만 `apply_patch` 사용. 자동 생성물이나 다중 파일 대량 치환 시에는 스크립트/도구를 고려.
  - 이미 존재하는 사용자 변경분은 되돌리지 않음. 저장소가 더럽다면 내가 건드린 부분만 수정.
- **대용량/중요 파일 다루기**:
  - 전부 출력하지 않고 `rg`, `head` 대용 Node 스니펫 등으로 범위를 좁힌다.
  - 이진/압축/에셋은 열람하지 않음; 메타데이터만 확인.
- **실행/빌드/테스트**:
  - 필요 시 `npm`/`pnpm`/`yarn` 스크립트를 실행할 수 있으나, 명시적으로 요청받거나 작업 검증에 필수일 때만 사용.
  - 실행 전후로 어떤 커맨드를 쓸지, 산출물이 무엇인지 간단히 보고.
- **Git 관련**:
  - 기본적으로 커밋/푸시는 하지 않음. 요청 시 `git status`, `git diff` 등 읽기용만 사용. 강제 리셋(`git reset --hard`, `checkout --`)은 금지.
  - 커밋이 필요하면 메시지/범위 먼저 확인하고 지시 없이 amend하지 않음.
- **네트워크/권한**:
  - 네트워크 허용 상태지만 불필요한 다운로드/설치를 자제. 민감 경로나 시스템 전역에 쓰기 작업은 피한다.
- **보고 방식**:
  - 변경 시 경로를 인라인 코드로 명시(`ai-roomchat/docs/...`), 요약 → 세부 → 후속 제안 순서로 전달.
  - 테스트를 못 돌렸다면 그 사실과 이유, 사용자 검증 단계 제안 포함.

필요한 커맨드나 절차가 새로 생기면 여기에 추가/수정해서 최신 상태로 유지한다.
