# WASM Runner PoC (client-side & server-side options)

목표: 템플릿 처리(치환, 간단한 변환 로직)를 안전하게 실행할 수 있는 WASM 기반 PoC를 제안합니다. WASM은 클라이언트(브라우저/모바일)와 서버(Wasmtime 등)에서 강한 격리를 제공하므로 안전한 대안이 됩니다.

핵심 아이디어
- WASM 모듈은 입력 JSON과 템플릿을 받아 렌더된 결과(또는 오류)를 반환합니다.
- WASM 모듈은 파일 시스템/네트워크 접근 권한을 갖지 않음. 모든 외부 I/O는 호스트(브라우저 또는 서버)에서 명시적으로 제공.

선택지
- 클라이언트 측: WASM 모듈을 브라우저에서 직접 로드(예: Wasm-bindgen, TinyGo → wasm)하여 즉시 실행. 장점: 네트워크/서버 부하 감소. 단점: 모바일 브라우저 성능 차이.
- 서버 측: Wasmtime 또는 Wasmer를 사용해 머신에서 안전하게 WASM을 실행. 네트워크/DB 접근이 필요하면 호스트 함수를 통해 제어된 방식으로만 제공.

PoC 구성 요소
1) 템플릿 엔진을 WASM으로 포팅(또는 작은 JS 엔진을 Wasm으로 컴파일). 우선 기능 제한된 엔진(치환 + 간단한 조건문)으로 시작.
2) 샘플 입력/출력 테스트 벤치(5개 케이스)와 벤치(성능 측정) 작성
3) 보안 테스트: 파일/네트워크 직접 접근 시도 차단 확인

성공 기준
- 브라우저에서 100ms 이하로 간단 템플릿(<=1KB)을 렌더링
- 서버측 Wasm에서 동시 50 요청을 처리할 때 평균 latency 50–200ms(하드웨어 의존)
- 모든 외부 접근은 호스트가 명시적으로 허용한 경우에만 작동
